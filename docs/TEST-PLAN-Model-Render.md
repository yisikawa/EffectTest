# NPC モデル描画 テスト計画（2026-11-09）

> 設計: `docs/DESIGN-Model-Render.md` / 計画: `docs/superpowers/plans/2026-11-09-model-render.md`
> 目的: P1（NPC モデル表示）が**原因レベル**で正しいことを判定する。
> **制約: ModelTest（`D:\projects\ModelTest`）は一切変更しない**（参照のみ。テストでも ModelTest を実行・書換しない）。

## 1. 目的と範囲

| 項目 | 内容 |
|---|---|
| 目的 | 選択した NPC DAT のメッシュ・骨・テクスチャ・モーションが設計どおり読め、画面に出ること |
| 範囲 | `0x2A`/`0x29`/`0x2B`/`0x20` の読込、スキン描画、カメラ整合、既存エフェクトの回帰 |
| 非対象 | PC パーツ合成、FBX 出力、影、4 面図、ボーン追従エフェクト、見た目の忠実度（V-15/V-16 の残差） |

## 4. 合否判定

- **自動（T1/T3）**: 期待文字列の完全一致。1 件でも欠ければ不合格
- **描画（T2）**: 画素数と PNG 差分で判定。**参照画像との一致は本計画の対象外**（P1 の受け入れは「出ること」まで）
- エフェクト側の数値が 1 つでも動いた場合は**不合格**（`GfxDrawQuad` 経路を触っていない証拠になる）

## 6. リスクと代替

| 症状 | 疑う箇所 | 代替判定 |
|---|---|---|
| モデルが真っ黒 | ライト・法線・テクスチャ | `--bg` を白にして輪郭で判定 |
| モデルが出ない | カメラ・スケール | `--selftest` の寸法ログ＋既知の AABB |
| エフェクトの数値が動く | `Gfx` の状態漏れ | M-10/M-11 を先に実行し、モデル実装前後で比較 |
