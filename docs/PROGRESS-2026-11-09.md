## 3. 今日の主要な発見（再現手順つき）

### 3.1 `0x1F`（ジオメトリ）
- ヘッダ **0x30 B 固定**、頂点は `0x30 + i*0x24`（36 B）、個数 = `+0x16（三角形数）× 3`
- 頂点: `+0x00/+0x02/+0x04` = half x/y/z、**`+0x1C` = half u / `+0x20` = half v**
- `+0x02` は**未初期化のことがある**（285 チャンク実測で 71 件）。1 軸の異常率 >30% なら軸を 0 固定、残りはクワッド内中央値
- テクスチャ名: `+0x1E` の 8 文字（グループ名）が `0x20` の名前の前半 8 文字と一致（例: `ic` → `ice1`）
- 検算: `f101` は `0x30 + 96*0x24 = 0xDB0` でチャンク末尾に一致

### 3.2 参照動画と似ない原因（数値）
| 画像 | 炎 bbox | 縦横比 |
|---|---|---|
| 参照 `frames/v_0062.png`（effect 3.0 s） | 136×336 | **0.40** |
| 当方（旧既定・横並び on） | 472×232 | **2.03** |
| 当方（横並び off） | 176×232 | **0.76** |

### 3.3 連続放出（`FUN_0040e0b0` / `FUN_00410090`）
- **VM#1 は生成時に 1 回だけ**、VM#2 が毎フレーム（旧実装は VM#1 を毎フレーム＝誤り）
- 寿命 = `ctx+0x1c8`、粒子ストライド = `+0x1c0 + 0x108`
- 放出: `ctx[0x50] -= dt` → しきい値 `ctx[0x58]` を割ったら `ctx[0x4c]` 個生成 → `ctx[0x58] -= ctx[0x54]`
- 再初期化: `elapsed/T01=0`、`Move -= rand()*2π`、`UV -= rand()`

### 3.4 op `0x06` の定数（逆アセンブルで確定）
```
0x452C60 = π/2 (double)
0x452C68 = 7.3145905998828198e-10 = π/65536
0x452C70 = 1.462918119976564e-09 = 2π/65536
rand() は 0..65535 の整数 → 定数は 65536 で前割り
```

### 3.5 キーフレーム補間（VM#2 `0x0F..0x21`）
- 出力先は **op で決まる**: `(op + 0x11) * 4` バイト
  - `0x0F..0x11` → Pos / `0x12..0x14` → Move（×π）/ `0x15..0x17` → Scale /
    `0x18..0x1B` → Color / `0x1C..0x21` → UV
- キー表は **VM#1 の `(0x20<op<0x30) | (0x32<op<0x37) | (0x58<op<0x5c)`** が
  `particle[dest+0x43] = 命令 dword2` で設定。表は 8 バイト `[time, value]`、線形補間

## 6. 注意点（次回ハマりやすい所）

- `g_Layout` は**必ず off**（on だと横帯になる）。比較時は `--layout on` を明示しない

- ビルボードの α は「VM が色を書いていない場合」の代替で **α=1 強制**している。
  この妥当性は未決（`colorSet` フラグの導入は設計変更として保留）
