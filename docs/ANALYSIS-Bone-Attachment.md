# インスタンス毎の骨指定（調査メモ / 2026-11-09）

> 対象: `0x07` の `0x02`/`0x03` で生成される 1 枚のビルボード（= インスタンス）を、
> **どの骨の座標系に載せるか**という設計課題。現状は「エフェクト全体で 1 本の骨」だけ。

## 1. 用語と現状の実装

| 用語 | 意味 |
|---|---|
| インスタンス | `EffectContext::Spawn()` が作る `MotionInstance`。1 枚の板。位置・拡大・色・UV を VM が決める |
| ルート変換 | インスタンスの `center` / `axisR` / `axisU` に掛ける 4x4。現在は `--bone N` で**全インスタンス共通に 1 本** |

```
[効果 DAT の VM] → instance.pos / scale / color / uv
                        ↓
              （ここに骨行列を掛けたい）
                        ↓
                 GfxDrawQuad(...)
```

現状（`--shot --bone N`）は**全インスタンスに同じ骨行列**を掛けるだけ。したがって
「手に付く炎」と「足元の煙」を分けることができない。

実測（`11\18` Fire II / 90 フレーム、human 基準）:

| 条件 | 非背景 |
|---|---|
| 骨なし（既定） | 2,694 |
| `--bone 0`（根） | 452 |
| `--bone 10` | 452 |

## 2. なぜ必要か（参照動画の観察）

`fire2.mp4`（Target=NPC）の 6.2 s には**性格の違う 3 層**が同時に出る。

| 層 | 見え方 | 付くべき場所（推定） |
|---|---|---|
| 炎 | 腕・脚に沿った細い炎 | 各部位の骨（腕/脚） |
| 赤い光点 | 胸元の小さな発光 | 胸部の骨 |
| 煙 | 体の左上へ流れる黒煙 | 体の中心〜頭 |

1 本のルートでは「全部が同じ位置・同じ向き」になり、この 3 層を再現できない。

## 3. 情報源の棚卸し（何が分かっていて、何が無いか）

| 候補 | 実測・確認結果 | 使えるか |
|---|---|---|
| **骨名** | 参照実装 `CBone::LoadBone` は `SetName(Name)` に**空のローカルバッファ**を渡す（`Model_Anim.cpp:136-147`）。`m_Name` は実質空 | ❌ **名前では引けない** |
| **エフェクト DAT の骨** | `11\17`/`11\18`/`11\22`/`12\43`/`162\50` に `0x29`/`0x2A`/`0x2B` は **0 件** | ❌ 効果側に骨情報なし |
| **generator ヘッダ（`0x05`）** | `+0x11` は**独立フィールドではない**。`+0x10` の 32bit id の 2 バイト目で、値は 4/40/44/84/172（サイズ様）で id と完全一致。骨 index ではない | ❌ 確定 |
| **`0x3D` ブロック** | `11\18` の 1 件は tag `3033` / 832 B / `+0x10` に ASCII `SeSep` → **名前表（音・パラメータ名）**。骨ではない | ❌ |
| **`0x19` ブロック** | `k007`(32B) / `k006`(48B) など float のキー列 → **数値カーブ**。骨ではない | ❌ |
| **モデル Schedule の op `0x05`/`0x03`** | `0x05` は `(a,b)` と名前4文字、`0x03` の `a` が直前の `0x05` の `b` と一致する例あり（`gurd`: 0x05 b=2 → 0x03 a=2 'vswy'、`shot`: 0x05 b=52 → 0x03 a=52 'mloc'）。ただし値域は **0〜760**（`131\6` の一意値: 1,2,23,25,…,100,128 / `27\82`: 〜760）で**骨 index 単独ではない**（フラグ・％・時間が混在） | △ **手掛かりだが未確定** |
| **timeline op** | `0x02` の `param` は生成時刻（秒×60）。他に骨 index らしき値は未発見 | △ 未確定 |
| **VM op（VM#2）** | `0x25` = サブオブジェクト 0x42 dword を子へ複製、`0x33`/`0x46` → `FUN_0040f8b0`、`0x45` = 親ボーン合成（我々は平行移動で近似） | △ `FUN_0040f8b0` を解析した結果**骨解決ではない**（下記） |
| **モデルの Schedule（`0x07`）** | `atk0` は `0x03 name=hwat`（= `0x2B` モーション名）/ `0x57 name=vatk`（入れ子）のみ。骨名は出ない | ❌ 骨指定なし |

## 4. `FUN_0040f8b0` の解析結果（2026-11-09）

`op 0x33` / `0x46` から呼ばれる関数を decompile した結果:

- 引数は `(effectRoot, float* outMatrix)`
- `in_EAX + 0x8c / 0x90 / 0x94` の **3 つの角度**から `cos/sin` で回転行列を作り、
  `param_2 + 0xc/0xd/0xe`（行列の `_41,_42,_43`）へ並進を書き込む
- 途中で `effectRoot + 0x1a8`（フラグ）と `+0x1d0`（軸方向のバイアス量）を参照

→ **「サブオブジェクトの角度から行列を合成する」処理**であり、**骨の検索は行っていない**。
したがって「どの骨に付くか」は効果側のコードでは決まらず、**呼び出し側（app）が effect root に
骨行列を渡している**と推測される（その結線は未観測）。

## 5. `0x05` / `0x03` の判定結果（2026-11-09・3 段階テスト）

| 指標 | `131\6`（NPC / 56 骨） | `27\82`（human / 94 骨） |
|---|---|---|
| `0x05` の総数 | 6 | 63 |
| `0x05.b < 骨数` | 4（2, 52, 56, 2） | **41** |
| `0x05.b >= 骨数` | 2（67, 100） | **22**（150, 200 など） |
| `0x03` の総数 | 17 | 66 |
| `b ≡ a` の対応 | 2 件（`gurd` b=2→a=2、`shot` b=52→a=52） | 5 件（93, 33, 150, 150, 150） |

代表例:

```
gurd  0x05.b=(2)     0x03.a=(2)      [2 OK]
shot  0x05.b=(52,56) 0x03.a=(52)     [52 OK]
cnf0  0x05.b=(67)    0x03.a=(25)     [25 --]
dead  0x05.b=(100,2) 0x03.a=(34)     [34 --]
casm  0x05.b=(150)   0x03.a=(0,150)  [150 OK]   ← 骨数 94 を超える
```

### 結論

- `0x05` の `b` と `0x03` の `a` は**同じ値空間**（対応が取れる）→ **オブジェクト（モーションスロット）のハンドル**
- ただし**骨数を超える値（100, 150, 200）が多数**あり、**骨 index ではない**
- したがって「効果インスタンス → 骨」の対応は、**モデルの Schedule のハンドルからは直接得られない**

→ **データからの骨指定は現時点で断念**。次のいずれかで決める必要がある。

1. ハンドル空間（パーツ表）と骨の対応を、メッシュ（`0x2A` の `OffsetBoneTbl` / `BoneTblNum`）から作る
2. AltanaView の app 側の結線（effect root に骨行列を渡す箇所）を解析する
3. **参照動画の「体に沿う」は、大きなクワッドが体を覆っているだけ**という可能性を検証する（＝骨は不要で寸法の問題）

> 3 は重要: `fire2noalpha.mp4` のクワッドは**巨大で体を覆う**もので、「骨に貼り付いている」ことの証拠にはなっていない。
> 実際、我々の既定レンダ（骨なし）でも**寸法が正しければ**参照に近づく可能性がある。

## 6. 実現案（4 つ）

### A. データ由来の骨 index を使う（本命）
- **前提**: どこかに bone index がある（`0x05 +0x11`、`0x02 param`、`0x19` キー表、`0x3D` パラメータ）
- **利点**: データが正で、任意の DAT に自動適用できる
- **欠点**: 現時点で**該当フィールドを特定できていない**
- **必要な作業**: `+0x11` の分布調査（全効果 DAT で 0..93 に収まるか）、`0x3D` の内容解析

### B. 呼び出し側（モデル側）の規則に従う（本命の代替）
- **前提**: AltanaView の effect root がモデルの骨を受け取る経路がある（`0x25`/`0x33`/`0x45`/`0x46`）
- **利点**: 「どの骨に付くか」はモデル側の設定なので、効果 DAT を汚さない
- **欠点**: **モデルの Schedule 側に骨指定が無い**ため、AltanaView 側の規則（op の意味）を解明する必要
- **必要な作業**: `FUN_0040f8b0` の decompile、`0x45` の対象（`puVar9[0x20..]` か別オブジェクトか）の確認

### C. 名前/系統によるヒューリスティック
- 例: `kemuri*`（煙）→ 体の中心、`fir*`（炎）→ 胸部、`dist` → 距離指定
- **利点**: すぐ実装でき、見た目が近づく可能性
- **欠点**: **根拠が無い**（推測）。別の DAT で破綻する。設計方針として採用したくない
- **位置づけ**: 検証用の暫定に限定（既定にはしない）

### D. 現状維持（全体で 1 本）
- **利点**: ゴールデンが安定。実装済み
- **欠点**: 参照の 3 層構造を再現できない

## 7. 推奨手順

1. ~~`FUN_0040f8b0` の解析~~ → **完了**（§4: 行列合成であり骨解決ではない）
2. ~~`0x05 +0x11` の分布調査~~ → **完了**（§3: id の 2 バイト目。骨 index ではない）
3. **`0x3D` / `0x19`** → **完了**（§3: 名前表・数値キー。骨ではない）
4. 残る候補は **モデル Schedule の `0x05`/`0x03` の `(a,b)`**（値域 0〜760 で混在）
   - 次の一手: `0x05` の `b` が「パーツ/ボーン」なのか「時間/％」なのかを、**同じ値が別 op と対応するか**で判定する
   - 併せて `0x02`（効果側）の `param` と、`0x05` の `b` の関係を調べる
5. データで決まらない場合は、**呼び出し側の規則（app 側の結線）**を解析する

> 現時点では「データからの確定」はできていないため、**`--bone-map`（下記）で仮説を検証できる状態**にしてある。

## 8. 決まったときの実装形（案）

```cpp
struct MotionInstance {
    int boneIndex = -1;      // -1 = ルート（従来）。骨は 0 始まりの配列番号
    ...
};
// Spawn 時: mi.boneIndex = ResolveBoneIndex(g, op);   // A か B の規則
// 描画時:
const float* M = (mi.boneIndex >= 0) ? skel.World(mi.boneIndex) : rootXform;
```

### 7.1 検証用に実装済み（`--bone-map`）

データからの確定前でも仮説を試せるよう、**インスタンス番号 → 骨番号（0 始まり）**のマップを実装した。

```powershell
# インスタンス 0 を骨10、1 を骨20 に載せる（他は変換なし）
.\x64\Release\EffectTest.exe --shot --bone-map 0:10,1:20 --motion idl0 "…\11\18.DAT" out.png
#   [shot] model=…\27\82.DAT bones=94 motions=130 motion=idl0 rot=mirrorY bone=0
#   [shot] bone-map=0:10,1:20 mapped=2 inst=11
```

| 指定 | mapped | 非背景（`11\18` / 90 フレーム） |
|---|---|---|
| なし | — | **2,694**（不変） |
| `0:10,1:20` | 2/11 | 2,591 |
| `0:10,1:20,2:30,3:40` | 4/11 | 2,050 |

- `--bone`（全体ルート）と `--bone-map` は**独立**。`--bone` を指定しなければ、マップ外のインスタンスは**変換なし**
- 骨は `Skeleton::World(index)` の配列番号（0〜bones-1）で指定する

検証は `--shot --model human --motion <name> --frames N` の画素と、
参照動画（`fire2.mp4` の 4.2 s / 6.2 s）との**層ごとの位置比較**で行う。
