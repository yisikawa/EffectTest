## 1. 逆コンパイルで確定した事実（根拠）

`AltanaView.exe`（2020/UPX → Frida メモリダンプ → `%TEMP%\av_unpacked.exe`, sha256 `6d9d803f…9318`）を
Ghidra 12.2 で解析した結果（`FUN_0040e650` = VM#1、`FUN_0040f4b0` = VM#2）。

| op | 実装（実測） | 意味 |
|---|---|---|
| `0x44` / `0x53` / `0x6A`（VM#1） | `p = new 0x1d8; p = FUN_0040d5a0(ctx->root, p, arg1 /*4文字名*/, ctx->duration); *dest = (float)p;` さらに 2 つの更新リストへ登録 | **子インスタンスを名前から生成し、そのポインタを dest スロットへ書く** |
| `0x3C`（VM#1） | `q = (void*)arg1; memcpy(q + 0xA0, this_particle, 0x108); FUN_0040e600(q, dt);` | **自分の粒子状態を指定オブジェクトの粒子領域へコピーして更新** |
| `0x25`（VM#2） | `if (*dest != 0) memcpy((int)*dest + 0xA0, this_particle, 0x108);` | 同上（毎フレーム側） |

**要点**
1. `dest` スロットには **オブジェクトのポインタが float のビット列として**入る（`*pfVar14 = (float)piVar11`）。
2. 参照先の「粒子」は **オブジェクト先頭 + 0xA0**、サイズ **0x108 B**（= 我々の `SubObject`）。
3. `0x44`/`0x53`/`0x6A` の引数 1 は**4 文字の名前**（`FUN_0040d5a0` に渡る）＝ generator 名。

→ つまり AltanaView は「**粒子が粒子を生み、状態を引き継ぐ**」モデル（トレイル/子エフェクト）。
我々の `SubObject::f[]`（値配列）では参照を保持できないため、ハンドル化が必要。

### 1.1 実データでの出現（2026-11-12 全数走査）

`11\0-19` / `12\0-19` / `0\0` の 41 DAT を走査した結果、**該当 op を持つのは以下だけ**:

| DAT | VM#1（0x44/0x53/0x6A/0x3C） | VM#2（0x25） |
|---|---|---|
| `11\10` `11\11` `11\12` `11\13` | 各 5 | 0 |
| `11\14` | 7 | 0 |
| `12\10` `12\13` `12\16` `12\19` | 各 2 | 0 |
| `12\11` `12\14` `12\17` | 各 3 | 0 |
| `12\12` `12\15` `12\18` | 各 4 | 0 |
| **`0\0`（base）** | **14** | **3** |
| `11\17` `11\18` `11\22` `12\43`（参照対象） | **0** | **0** |

**結論（優先度への影響）**
- 本機構は **`11\10-14` / `12\10-19` / base `0\0`** でしか使われない。
- **fire2（`11\18`）の見た目は 1 ピクセルも変わらない**（該当 op が 0 回）。
- したがって「参照動画に近づける」目的では**優先度は低い**が、
  `0\0`（全エフェクト共通の土台）と `12\10` 以降の再現には必要。

## 2. データモデル

### 2.1 ハンドル

```cpp
// 32bit ハンドル: [generation:8][index:24]（index は m_Instances の添字）
struct ParticleRef { uint32_t raw = 0; };        // 0 = 無効
//   index は最大 16,777,215、generation は再生/破棄ごとに +1
```

- 生成: `Spawn()` が `m_Instances` に追加した直後に `index | (gen << 24)` を返す。
- 失効: `MotionInstance` に `uint8_t gen` を持たせ、`expired` で削除するときに世代を進める
  → 古いハンドルは「世代不一致」で**無効と判定**できる（ダングリング参照を安全に無視）。
- 参照の寿命: 参照側の粒子が生きているあいだのみ有効。無効なら **何もしない**（元実装の `if (*dest != 0)` と同じ）。

### 2.2 粒子側の保持

```cpp
struct SubUnit {
    ...
    uint32_t ref[SUB_DEST_N] = {};   // dest ごとの ParticleRef.raw（0 = 無効）
    uint8_t  refGen[SUB_DEST_N] = {};// 参考: 書き込み時の世代（デバッグ用）
};
```

- `keyFirst/keyCount/keyCur` と同じ「dest 添字」で並べる（元実装の `particle[dest+0x43]` と同じ位置）。
- 追加コスト: **+320 B/粒子**（512 粒子 × 12 インスタンスでも +2 MB 未満）。

## 3. 実装仕様

### 3.1 `0x44` / `0x53` / `0x6A`（VM#1: 子インスタンス生成）

```
arg1 = 4 文字名（generator 名）
dest = 出力スロット
```
1. `Spawn(name4, startSec = 0, op)` を呼ぶ（既存関数を再利用）。
2. 成功したら `su.ref[dest] = handle`、失敗（名前未解決）なら `su.ref[dest] = 0` とし、
   `[spawn] generator not found: …` の既存ログに集計を足す。
3. 元実装は更新リストへ登録して毎フレーム更新する（＝生成した子も寿命で消える）。
   我々の `m_Instances` は全件毎フレーム更新なので**追加作業なし**。

> 差分: 元実装は `new` した直後に `**(code**)(*p+4)()` 等の vtable 呼び出しを行うが、
> これはコンストラクタ/初期化に相当。我々は `MotionInstance::Reset()` が同義。

### 3.2 `0x3C`（VM#1）/ `0x25`（VM#2）: 粒子状態の転写

```
ref = su.ref[dest]（無効なら何もしない）
target = その MotionInstance
memcpy(&target->subs[0].sub, &su.sub, sizeof(SubObject));   // 0x108 B
```
- 元実装は `q + 0xA0` に書く（= オブジェクトの粒子領域の先頭）。我々は `subs[0].sub` が同義。
- `0x3C` は転写後に**その子の更新**を行う（`FUN_0040e600`）。我々は次フレームの `Eval` で行うため、
  `0x3C` では転写のみ。差分は 1 フレーム（60 fps で 16.7 ms）。
- 転写対象は `SubObject` 全体（0x108 B）なので、`keyFirst/keyCur/uv` など `SubUnit` 側の付随情報は
  **コピーしない**（元実装も 0x108 B のみ）。

### 3.3 フラグ

| フラグ | 既定 | 意味 |
|---|---|---|
| `--link on\|off` | **off** | 0.3.1/0.3.2 のハンドル機構を有効化（off は従来どおり未実装扱い） |

既定 off の理由: 子インスタンス生成は**インスタンス数が跳ね上がる**可能性があり、
ゴールデン（`docs/GOLDEN.md`）とメモリ上限（`subs < 512`）に影響するため、A/B で確認してから既定化する。

### 9.3 VM の確定事項

| 項目 | 実測値 |
|---|---|
| VM#1 | `0x40e650`（`ctx+0x24` = プログラム、`gen+0x10` = id、`gen+0x24` = プログラム） |
| VM#2 | `0x40f4b0`（`ctx+0x28` = プログラム） |
| 呼び出し元 | VM#2 ← `0x40e0b0`（生成）/ `0x40e650`（VM#1）/ `0x410090`（再初期化） |
| VM#2 の実 op | `2,3,5,6,8,9` / `0x0F..0x21` / `0x27,0x28` / `0x2C` / `0x34..0x37` / `0x25,0x33,0x46` |
| 未知 op | `0x0D` `0x0E` `0x5F` `0x29` `0x2B` は**元実装でも handler が無くスキップ**（→ opstat の値は正常） |
| キー補間 | `0x40f820`。**前進時はキー間の絶対補間／非前進時は現在値基準**の非対称。表は `+0x18` の 8 B `[time,value]` |
| attached | `ctx+0x1a0 != 0` は**行列コピーを省くだけ**。VM は実行する（旧実装の「VM 停止」は誤り） |
| `0x1F` | **実アセンブリで確定**（下記）。Z(arg5) → Y(arg6) の順 |
| 回転の実体 | `0x457084 → 0x42ed2b`（RotZ）、`0x457080 → 0x42ec88`（RotY）、`0x45700c → 0x436695`（合成）。**D3DX は静的リンク**（`d3dx9_*.dll` は無い） |
| `0x44`/`0x53`/`0x6A` | `new 0x1d8` + 名前（`arg1`）から生成し、**ポインタを dest スロットへ float で格納** |
| `0x3C` / `0x25` | `memcpy(obj + 0xA0, particle, 0x108)`（＝本設計の対象） |
| 該当 op を持つ DAT | `11\10-14` / `12\10-19` / `0\0`（**`11\17` `11\18` `11\22` `12\43` は 0 回**） |

**`0x1F` の確定式**（`0x40eb97: cmp $0x1f,%al` 以降の実アセンブリ。`%esi` = 引数先頭）:

```
A(位相) = rand() × arg0 × 1/65536 + arg1
B(方位) = arg10 ≠ 0 ? (ctx+0x1c4 × 2π) / (arg10+1) : rand() × 2π/65536
         B += A
C(仰角) = arg7 + (2·rand()−1) × arg8
v       = ( arg2·cosC·cosB,  arg3·sinC,  arg4·cosC·sinB )     ← 軸ごとの半径
v      := RotZ(arg5) · v
v      := RotY(arg6) · v
(arg9 == 1 かつ (ctx+0x1a8 & 0xC) ≠ 0xC のとき Rot? をもう一度適用)
pos    += v
```
