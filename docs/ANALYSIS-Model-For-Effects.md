# 調査: エフェクト描画にモデルの骨・アニメは必要か（2026-11-09）

> 問い: 「エフェクト描画に必要なのはボーン（スケルトン）とアニメーションだけではないか」（ユーザー指摘）
> 結論: **エフェクト単体の再生には骨もメッシュも不要**。参照動画（モデルに当てた記録）を再現するには**骨のワールド行列だけ**必要で、**メッシュは不要**。

## 1. 実測（読み取りのみ）

### 1.1 エフェクト DAT のチャンク構成

| DAT | 0x29 骨 | 0x2A メッシュ | 0x2B モーション | 主な中身 |
|---|---|---|---|---|
| `11\17`（Fire） | **0** | **0** | **0** | `0x05`×8, `0x20`×5, `0x21`×3 |
| `11\18`（Fire II） | **0** | **0** | **0** | `0x05`×11, `0x19`×10, `0x20`×7, `0x21`×5, `0x1F`×1 |
| `11\22`（Blizzard） | **0** | **0** | **0** | `0x05`, `0x20`, `0x21` |
| `12\43`（Foe Requiem） | **0** | **0** | **0** | `0x07`×2, `0x20`×6 |
| `162\50` | **0** | **0** | **0** | `0x07` のみ |

→ **エフェクト DAT は骨・メッシュ・モーションを一切持たない。**

### 1.2 モデル DAT（`131\6` = NPC ROM1）の構成

| 種別 | 件数 | レイアウト（ModelTest の読込コードより） |
|---|---|---|
| `0x29` 骨 | **1 チャンクに全ボーン** | `+0x12` = 本数（short）、`+0x14` から **30 バイト/本**（`quat(16) + translation(12)` + 2 バイト） |
| `0x2B` モーション | 18 | ボーン別キーフレーム |
| `0x2A` メッシュ | 4 | ヘッダ 64 バイト + ポリゴン/ボーン表/ウェイト/頂点 |
| `0x20` テクスチャ | 2 | TIM/DXT |
| `0x07` Schedule | 39 | `0x2B`/`0x3D` を参照 |

### 1.3 モデルの Schedule は骨を参照しない

`--action "…\131\6.DAT" atk0` の実測:

```
[action] atk0 insts=6 dur=0.017s
  +0x050 op=0x01 len=2 delay=0 param=0 name=
  +0x058 op=0x03 len=4 delay=0 param=0 name=hwat     ← 0x2B モーション名
  +0x068 op=0x57 len=4 delay=0 param=0 name=vatk     ← 0x07 入れ子
  +0x078 op=0x24 len=2 delay=1 param=0 name=2
  +0x080 op=0x32 len=2 delay=0 param=0 name=
  +0x088 op=0x00 len=2 delay=0 param=0 name=
```

→ 参照するのは**モーション名**（`hwat`/`vatk`）で、**骨名ではない**。

## 2. 結論

| 目的 | 骨（0x29） | モーション（0x2B） | メッシュ（0x2A） |
|---|---|---|---|
| **エフェクト DAT を単体で再生**（EffectTest の現行用途） | 不要 | 不要 | 不要 |
| **参照動画の再現**（モデルに当てた状態） | **必要**（骨のワールド行列） | **必要** | **不要** |
| モデルの見た目を出す（P1 本来） | 必要 | 必要 | **必要** |

- エフェクトの位置は、エフェクト自身の VM（`SUB_POS`/`SUB_SCALE`）が生成する。
  参照動画が「体に沿う」のは、AltanaView が **Target=NPC** でモデルの骨にエフェクトを結び付けて再生したため。
- ただし **エフェクト DAT 側に骨参照が無い**（1.1）。したがって「どの骨に付くか」は**呼び出し側**が決める。
  この結び付き経路（AltanaView の effect root ⇄ 骨）は**未確定**で、追加調査が必要。

## 5. 実装結果（P1a: 骨＋モーションのみ）

`Skeleton.h/.cpp` を追加し、`--skel "<dat>" [motion]` で検証できるようにした。

| 項目 | 実測（`ROM\131\6.DAT`） |
|---|---|
| 骨 | **56 本**（`0x29` 1 チャンク、44 + 56×30 = 1,724 B） |
| モーション | **18 本**（`atm1` 0.95s/33keys, `cor0` 1.00s/2keys, `ded0` 0.50s/26keys, `idl0` 0.35s/15keys, `ma00` …） |
| 静止姿勢 | bone0=(0,0,0) / bone1=(0.123,**-1.151**,-0.123) / bone7=(0.039,-0.542,-0.247) |
| `idl0` 適用 | mid が t=0→1.0 で (-0.471) → (-0.475)（微変化＝待機モーションとして妥当） |
| モーション差 | `idl0` mid.x=0.214 / `cor0` mid.x=1.005（モーション毎に姿勢が変わる） |
| エフェクト回帰 | `11\17` = **8,050 / 348**（不変） |

**実装で判明した重要事項**
- `fdat` は「DAT2B 配列の**先頭**」を指す `float*` で、`idx` はそこからの float 番号（レコード配列の 21 dword × 要素数を超えるとキー配列）。
  最初これを「配列の後ろ」と誤解し、全ボーンが原点に潰れた。
- 合成は ModelTest の `DynamicTransform` と同じ
  **`world = rest * motion` → `*= parent.world`**（行ベクトル規約）。キーは rest に対する**差分**。
- `SetMotionName` の「先頭 2 桁が数字なら入れ替える」癖も再現した。

**未確定（P1a の残り）**
- 静止姿勢で y が負（足元が -1.15）。FFXI の座標系（Y 下向き or ルート回転）は未確定。
  メッシュ（P1b）を入れれば即座に判別できる。

## 6. ルート変換（左手系合わせ）— 解決

> ユーザー指摘: 「ボーンを DX11 左手系に合わせるため、ModelTest では最初に回転させています」

参照実装で確認した実体:

| 箇所 | 内容 |
|---|---|
| `Model_Common.cpp:23-25` | `matrixMirrorX = diag(-1,1,1)` / **`matrixMirrorY = diag(1,-1,1)`** / `matrixMirrorZ = diag(1,1,-1)` |
| `Model.cpp:646-648`（`DynamicTransform`） | 親合成の**後**に全ボーンへ `m_mRootTransform` を掛ける |
| `Model.cpp:579`（`InitTransform`） | 既定は identity。呼び出し側が `matrixMirrorY` を設定する運用 |

### 実装（`Skeleton::SetRootMode`）

親の world を先に合成しているため、「根に 1 回掛ける」のと等価。モードを切替可能にした。

| モード | 変換 | `131\6` bone1 の原点 | `last` |
|---|---|---|---|
| `none` | なし | (0.123, **-1.151**, -0.123) | (-0.187,-0.306,-0.525) |
| **`mirrorY`（既定・ModelTest と同一）** | `diag(1,-1,1)` | (0.123, **+1.151**, -0.123) | (-0.187, **+0.306**, -0.525) |
| `rotX180` | X 軸 180° | (0.123, +1.151, +0.123) | (-0.187, +0.306, +0.525) |
| `rotZ180` | Z 軸 180° | (-0.123, +1.151, -0.123) | (+0.187, +0.306, -0.525) |

- **既定を `mirrorY`（ModelTest と同一）**にした。これで骨が根より上（y>0）に来て姿勢が妥当になる
- `--skel "<dat>" [motion] [none|mirrorY|rotX180|rotZ180]` で比較できる（`rot=` をログ出力）
- 左手系を保ったままにするなら `rotX180`/`rotZ180`（＝回転）を選べる。**P1b でメッシュを入れた時点で、
  参照（ModelTest）と一致するモードを確定する**

## 7. 設計への反映

- P1 を 2 つに分割する:
  - **P1a: 骨＋モーションのみ**（`0x29` + `0x2B` の読込とワールド行列更新）。メッシュ不要。**0.5〜1 日**
  - **P1b: メッシュ描画**（`0x2A` + スキン描画 + テクスチャ）。**1.5〜2 日**
- EffectTest の現行目的（エフェクト表示・Schedule 列挙）には **P1a も必須ではない**。
  参照動画の再現、または「モデルの上でエフェクトを確認したい」場合に P1a を実施する。
- **次の最優先は引き続き「エフェクト自身の空間の正しさ」**（寸法・位置。`docs/VERIFY-PLAN-Schedule.md` V-16）。
  骨を入れても、エフェクトの寸法が横長のままでは参照に近づかない。
