## 1. 事実（推測ではなく実測）

### 1.1 Cure の VM#1 実プログラム（バイトコード直読み）

`tblB` を `op=w0&0xFF / len=(w0>>8)&0x1F / arg=+4` で展開した結果:

### 1.2 VM#2（`tblC`）

| gen | VM#2 |
|---|---|
| prn1 | `0x0E` → `0x02` d13 → `0x05` d9 → `0x15` d6 → `0x16` d3 → `0x1B` d0 |
| kr10 | `0x0E` → `0x02` d13 → **`0x29` d9 (0.1222,-0.1222,-0.0175)** → **`0x2B` d9 (0.1222,-0.1222,0)** → `0x15` → `0x16` → `0x1B` |
| kr11/kr12 | `0x29`/`0x2B` **なし** |

→ **`0x3D`/`0x3E`/`0x40`（VM#1）と `0x29`/`0x2B`（VM#2）は kr10 にだけ対で現れる**。

### 1.3 決定的な欠落: Move スロットが使われていない

```
grep 'SUB_MOVE|0x8C' App.cpp Effect.cpp Gfx.cpp
→ ヒット 0（Effect.cpp の 0x8C は tblD のオフセットで無関係）
```
- VM#1 `0x09` は Move(0x8C) に **(-2.4783, 0, 0)** を書く。
- VM#2 `0x05` は Move に `k*d` を積む。
- しかし**描画側は `SUB_POS` しか読まない**。Move は捨てられている。

### 1.4 数値の整合

- prn の寿命 = `(frames+1)/60` = **0.167 s**
- `|Move| = 2.4783 m/s` → 0.167 s で **0.41 m**
- 参照画像の白い星は体中心から **0.4〜1 m** に散在 → **一致**
- 回転 0x3B で向きが変わる（100° / 80°）。回転はベクトル長を保つので `|Move|` は不変（2.4783 のまま）→ 整合
- 我々の出力は `pos=(0,-1.31,0)` = x=z=0 の直線。Move を積分していないため、`0x02` d13 の -0.041 成分だけが効いた姿

## 2. 実装する仮説

| ID | 仮説 | 確度 | 根拠 |
|---|---|---|---|
| **H-A** | **Move(0x8C) を位置に積分する**（`pos += move * dt`） | **高** | §1.3 の欠落。Move の値と寿命から 0.41 m が出る。これが無いと prn/kr は必ず x=z=0 の直線 |
| **H-B** | **`0x3B` = Move を固定角回転**（arg0=X, arg1=Y, arg2=Z ラジアン） | **高** | prn0/prn1 で角度だけが 80°/100° と違い、`0x09` のベクトル長と組み合わせて扇状の向きを作る。回転なら長さ不変 |
| **H-C** | **`0x3A` = Move の散布/乱数化**（9 引数、arg7=FLT_MAX は「クランプ無し」の歩哨） | 中 | prn0/prn1 で引数が完全一致（共通の散布パラメータ）。arg1/arg2 = 3.8 / 6.4 rad は角度レンジ（217°/367°）と読める |
| **H-D** | **`0x3D`/`0x3E`/`0x40`（VM#1）+ `0x29`/`0x2B`（VM#2）= スピン**（面内回転角の初期化と毎フレーム積分） | 中〜高 | §1.2 の対の出現。`0x3D` は len=1（引数なし＝0 初期化）、`0x3E`/`0x40` は ±(0.04,0.02)、`0x29`/`0x2B` は ±0.1222 rad（≈7°）。kr11/12 は両方とも無い |
| **H-E** | 明るさ・合成（加算 / RGB×2 / α×4 / αref=32） | 高 | `ANALYSIS-AltanaView-RenderStates-2026-11-13.md` §6 で実測済み。H-A〜D の後に適用 |

### H-A の式
```
pos += move * dt        // move は m/s、dt はフレーム時間
```
- 実装位置: `Effect::Update`（`Vm2` の直後、全サブ）。`--moveint on|off`（既定 on で検証、off で従来）
- 注意: `RespawnSub` が Move に乱数位相を足している（`-rand*2π`）。これは「0x3B/0x3A で使う位相」の名残なので、H-A 適用後に**位相の意味が変わる可能性**がある → フラグで A/B。

### H-B の式（VM#1 の `case 0x3B`）
```
Move = RotZ(arg2) * RotY(arg1) * RotX(arg0) * Move
```
- 実測順序（`0x1F` で確定済み: Z→Y）を踏襲。

### H-C の設計（断定しない）
- 第 1 段: `0x3A` の前後で**粒子構造体を Frida で差分観測**し、書込み先を特定（Move か Pos か dest か）
- 第 2 段: 特定後に `--scatter` フラグ付きで実装

### H-D の設計
- VM#1: `0x3D` → スピン角 3 成分を 0 に。`0x3E` → `angle += rand(-arg0..arg0)` 等。`0x40` → 同（符号差の可能性）
- VM#2: `0x29`/`0x2B` → `angle += k * arg`（既存 `0x03/0x06/0x09` と同じ積分形）
- 描画: `axisR/axisU` を視線軸まわりに `angle[2]` 回転（`App.cpp` ビルボード部に追加）

## 3. 実装順序（小さく刻む）

1. **H-A**: `Effect::Update` に Move 積分 + `--moveint` フラグ
   検証: `--trace` で prn の x/z が 0 でなくなる／移動量 ≈ 0.4 m
2. **H-B**: `EffectVm.cpp` に `case 0x3B`
   検証: prn の星が**放射状に 2 方向**（80°/100°）へ分かれる
3. **H-D**: `0x3D/0x3E/0x40` と `0x29/0x2B` + 描画回転
   検証: kr の星が回る（連続フレームで角度変化）
4. **H-C**: `0x3A`（Frida 確定後）
   検証: 星の**個数と散らばり**が参照に一致
5. **H-E**: 加算合成・RGB×2・α×4・αref
   検証: `maxSum` が 346 → 700 超（白飛び）

## 6. リスクと撤退条件

- **Move 積分が他 DAT を壊す**: `--moveint off` で完全に従来へ戻せること（既定を off にして段階導入も可）
- **0x3A の誤解釈**: 引数に FLT_MAX を含むため、誤って適用すると座標が発散する。**必ずクランプ**を入れ、`--scatter` で隔離
- **スピン角のスロット仮説が外れた場合**: `0x29/0x2B` は「UV 揺らぎ」等の可能性が残る。描画に影響させず、まずスロットへ書くだけにして観測
- 撤退条件: T-5 が ±2% を超えた時点でその段を revert
