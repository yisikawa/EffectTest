# 実装計画: 1 generator = 複数サブ（粒子）

- 日付: 2026-11-09
- ブランチ: `feature/schedule`
- 根拠: `docs/ANALYSIS-AltanaView-Draw.md` §3（`count = byte@+0x78 + 1`、stride `0x108 + count*4`、
  VM#1/VM#2 は **サブごとに** 実行 = `FUN_0040e600` のループ）。実測: `12\43` の `g006` は 12、
  `g011`/`g010` は 4、`162\50` の `csh1` は 3。`11\18`/`11\17`（Fire 系）は全て 1。

## 1. 目的

エフェクトの粒子数を AltanaView と一致させる。Fire 系（count=1）は**挙動を一切変えない**こと
（既存ゴールデン `11\17` 8,050/348、`11\18` 2,694/576 を維持）。

## 2. 設計

`MotionInstance` が 1 個の `SubObject` を持つのをやめ、**サブ配列**を持つ。

```cpp
struct SubUnit                       // 粒子 1 個ぶんの状態
{
    SubObject sub;                   // VM の出力先（0x108 + N）
    float     uv[4]        = {0,0,1,1};
    int       frameIdx     = 0;
    float     quadHalf[2]  = {0,0};
    float     quadCenter[2]= {0,0};
};

struct MotionInstance
{
    ...
    std::vector<SubUnit> subs;       // サイズ = gen->count + 1
};
```

- `Reset()` で `subs.assign(gen->count + 1, {})`、各サブを `Clear()` し、
  `T01/Elapsed/prev` と初期色（op 0x2A の直近色）を設定
- `Eval()` は **サブごとに** VM#1 → VM#2 → 0x21 フレーム更新
- 描画は **インスタンス × サブ** の二重ループ。`GfxDrawQuad` はサブ単位
- 乱数（`Rand01`）はサブごとに消費 → AltanaView と同じ「粒子ごとに揺らぐ」挙動

## 3. 手順

1. `Effect.h`: `SubUnit` 追加、`MotionInstance` の `sub/uv/frameIdx/quadHalf/quadCenter` を `subs` へ置換
2. `Effect.cpp`: `Reset()`（`subs` 初期化）と `Spawn()`（初期色を全サブへ）
3. `EffectVm.cpp`: `Vm1(SubUnit&, ctx)` / `Vm2(SubUnit&, dt, dur)` へ引数変更、`Eval()` をサブループに
4. `App.cpp`: 描画をサブループに、ログ/トレースはサブ 0 を代表として出力（`subs=N` を併記）
5. ビルド → 回帰（`11\17`/`11\18` が不変）→ `12\43` の変化を確認

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| Fire 系のゴールデンが動く | count=1 のとき `subs.size()==1` で従来と同一経路を通す（ループ回数 1） |
| 乱数消費が増えて他が変わる | `Rand01` はサブごとに消費（AltanaView 準拠）。Fire 系は 1 サブなので消費数は不変 |
| 描画コスト増（12 倍） | 影響は `12\43` 等のみ。1 サブは従来同等 |
