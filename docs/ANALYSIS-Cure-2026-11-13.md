## 1. ターゲット（Cure = `10/9`）の確定手順【重要・再発防止】

これまで Cure IV を撮ってしまっていた原因は 2 つ。両方潰した。

### (a) 選択は ini で固定する
`AltanaView.ini` の
```
[Effect]
Item=0
```
が Cure（`10/9.DAT`）に相当。`Item=3` は Cure IV（`10/12.DAT`）。
ツリーの座標クリックは **`TVM_GETITEMRECT` が別項目の矩形を返す**ため不安定で、
`TVM_SELECTITEM`＋通知偽装・`TVM_EXPAND` も効かなかった。**ini 固定が唯一安定**。

### (b) 「Play」ボタンは ID 1043（1051 ではない）
`AltanaView` の子ウィンドウを列挙した実測（Effect タブ）:

| ID | テキスト | 位置 (L,T) | 用途 |
|---|---|---|---|
| 1051 | Play | 463, 694 | **キャラのスケジュール**再生（押しても絵が変わらない） |
| 1045 | Play | 463, 723 | モーション再生 |
| 1057 / 1047 | Stop / Reset | 400,762 / 463,762 | |
| **1043** | **Play** | **527, 781** | **エフェクト（Schedule / 3）の再生 ← これ** |
| 1082 | Play target's schedules. | 310, 850 | ターゲット側スケジュール |

`1051` を `BM_CLICK` しても **24 フレームすべて差分 0 px**（＝エフェクトは動かない）。
`1043` に変えた瞬間に 1262→9317 px の差分が出た。

### (c) 毎回 DAT を検証する
再生前・再生後にステータスバー（`msctls_statusbar32`, `SB_GETTEXTW`）を読み、
`...\ROM\10\9.DAT` であることを確認。違えば中断。

再現コマンド（要 `AltanaView.ini` の `[Effect] Item=0`）:
```
Stop-Process -Name AltanaView
Start-Process 'D:\tool\AltanaView-master\AltanaView.exe' -WorkingDirectory 'D:\tool\AltanaView-master'
# 起動 4 秒後: ステータスバー検証 → ID 1043 を BM_CLICK → 連続撮影
pwsh -File %TEMP%\av_cure\burst.ps1 -Count 24 -IntervalMs 150
```

## 4. 原因（未実装 op）

Cure（`10/9`）で実際に走る op のうち、**我々に実装が無いもの**:

### VM#1（粒子生成時に 1 回）

|---|---|---|
| **`0x3A`** | 140 | 最重要候補 |
| **`0x3B`** | 140 | 最重要候補 |

| `0x3D` / `0x3E` | 各 56 | |
| `0x72` / `0x2D` | 各 390 | **元実装にも handler 無し**（無視してよい） |

### VM#2（毎フレーム）
| op | 回数 |

### 9.3 四芒星が出た（マイルストーン）

`--blend alpha_add --gain 4 --keymode norm --moveint on --ringscale 1 --size meter --scale 0.25
 --res 833x709 --dist 2.785 --colorfallback off`、frames 150:

- `nonBg = 23,492` / `maxSum = 765`

→ 参照 Cure の「白い四芒星」と同じ質感に到達。残差は
**サイズが大きすぎる**（`--scale 0.25` は 1 m フォールバックへの倍率）、
**位置の分布**（上下に偏る）。次段は ffxitool5 の頂点生成式から
「0x21 実寸 × VM Scale」の正しい基準を決める。


1. **サイズ**: 0x21 が無い generator は `--size meter` の 1.0 m 固定になり、
   prn の星が 1 m 角になって潰れる。`quadHalf` が 0 のときの基準寸法を決める必要がある
2. **α / 色**: prn の α は 0.006〜0.09（AltanaView の頂点 α 1〜64/255 と同水準）。
   AltanaView は α を ×4、RGB を ×2 して加算するため白飛びする。PS 側の実装が必要
3. **個数**: 放出レート 24/s は 11\18 向けの暫定値。Cure の参照は星 10 個程度

## 9. ffxitool5 解析の反映（2026-11-13 追加）

`docs/ANALYSIS-ffxitool5-2026-11-13.md` で得た知見を EffectTest に反映した。

| 追加 | 内容 | 既定 |
|---|---|---|
| `--keymode norm` | ffxitool5 `FUN_00403940` 方式（0..1 正規化・区間探索・線形補間） | incr（従来） |
| `--blend alpha_add` | 既存。ffxitool5 は `SRCALPHA + ONE`（加算） | alpha |
| `--gain 4` | 既存。ffxitool5 は `COLOROP = MODULATE4X`（RGB ×4） | 1.5 |

**計測結果（Cure 10/9, `--frames 45`, `--moveint on --ringscale 1`）**

| keymode | prn0 α | prn1 α |
|---|---|---|
| incr（従来） | 0.006 – 0.073 | 0.006 – 0.088 |
| **norm（新）** | **0.000** | **0.000** |

→ `norm` にすると α が **0 に落ちる**。つまり prn の α トラック（`prx0`）の
**キー表の読み方（`keyFirst` / `count` / 時間軸の単位）がまだ正しくない**。
incr 側の 0.006〜0.088 は「増分補間のドリフト」で出ていた値で、実データ由来ではない可能性が高い。

**次の一手**: Cure の `0x19` チャンク（`prx0` / `k1x0` / `k3x0`）の生バイトを読み、
`(size-0x18)/8` 件の `[time, value]` が **秒かフレームか**、**昇順か**、
先頭に終端（1.0）が来ていないかを確認する。

回帰は維持: `11\17=9,310` / `11\22=962` / `12\43=4,764`、`--selftest` も
`keys 8/8 resolved, 0 unresolved`・`rebuild = ok`。
